# 数据界面：看板、指标卡与自助分析

适用于指标看板、报表、数据详情、自助查询/BI、数据产品后台。数据界面和普通页面最大的区别：**用户不只问「怎么操作」，还问「这个数能不能信」**。信任问题不解决，交互做得再顺也没人用。

## 1. 先定四件事，再画界面

| 要素 | 必须写清 | 缺失的后果 |
|---|---|---|
| 口径 | 公式、分子分母、排除项、口径版本 | 两个人看到两个数，开始对数 |
| 时间 | 时区、数据截止时间、默认范围、对比期 | 「昨天」指哪一天说不清 |
| 权限 | 能看到什么、不能看到什么、怎么申请 | 用 0 或空白冒充无权限 |
| 对比 | 与上期/同期/目标比，还是只看现值 | 有数但无法判断好坏 |

界面上的每个指标，至少要能回答：**这是谁的数、从哪来、什么时候的、变了没有。**

## 2. 指标卡与看板

- 指标卡结构：名称 + 当前值 + 对比 + 口径/来源入口 + 更新时间。
- 数值要有单位、精度、缩写规则（万/亿、百分比），同一页面统一。
- 空值、0、未就绪、无权限是四件事，不要都显示 `0` 或 `--`。
- 看板先给「结论区」（核心 3–6 个指标），再给下钻；不要把 30 张图平铺。
- 下钻保持筛选、时间范围、对比期一致；返回时恢复原视图。

## 3. 数据特有的状态

在通用异步状态之外，数据界面多出 5 个状态：**数据未就绪、部分数据、数据延迟、口径变更、样本不足**。完整状态表见 [states.md](states.md) §11，这里不再重复维护。

数据界面额外注意：导出/计算中要能离开再回来；无权限不能画成空或 0；部分数据要标明缺哪一段、哪个渠道。

## 4. 权限三层，界面要分别表达

1. **人—指标权限**：在指标定义层授予，决定「能不能看到这个指标」。
2. **导出/API 权限**：申请—调用—鉴权，授权对象是应用而不是个人。
3. **加工后数据权限**：拥有底层指标权限 ≠ 拥有加工后的 API/宽表权限，加工逻辑本身可能是业务隐私。

界面要求：无权限给出原因与申请路径；部分字段脱敏要说明；导出、批量查询要有审计与上限提示；不要把「无权限」画成「无数据」。

## 5. 降低核对成本（数据界面的核心交互）

用户核对一个数，通常要做四个动作，每个动作都应有界面机制：

| 动作 | 界面机制 |
|---|---|
| 这是谁的数 | 口径卡片、负责人、数据源 |
| 从哪来 | 血缘/来源链接、加工说明 |
| 什么时候的 | 截止时间、更新频率、时区 |
| 变了没有 | 对比期、变更记录、口径版本 |

## 6. 表格、筛选与导出

- 默认时间范围写出来，不要默认「全部」；大数据量默认聚合。
- 筛选条件可分享、可恢复（URL 参数），返回不丢。
- 排序与分页对聚合值要说明是「先聚合后排序」还是「先排序后聚合」。
- 导出口径与页面一致，包含列头、时间范围、口径版本；导出任务可追踪。
- 界面计数、分析计数、下钻样本数与导出条数要能互相对上；折叠转载、去重、打包造成的差异就地标注（如「展示 232 条 / 原始 234 篇」）。
- 同一能力出现在多个入口（全站看板、筛选内分析、单页图表）时，各自默认时间窗与样本范围就地写明，避免同一个「导出」产出两份不同范围的数据。
- 数字右对齐、单位统一；空与 0 分开表达。

## 验收清单

- [ ] 每个指标有口径入口、来源、更新时间、对比期
- [ ] 未就绪/部分数据/延迟/口径变更/无权限/样本不足都有独立状态
- [ ] 无权限不被画成空或 0
- [ ] 权限三层（指标、导出/API、加工后）在界面上有对应表达
- [ ] 筛选、时间范围、对比期可分享可恢复
- [ ] 导出含口径与时间范围，且有权限与审计
- [ ] 页面计数、下钻计数与导出条数能对上，差异有说明
- [ ] 同一能力的多入口默认范围有就地说明
- [ ] 数字格式、单位、空值规则统一
