# 表单

表单是用户输入成本最集中的地方，也是产品经理最容易把它当成「字段清单」的地方。这里按「字段 → 校验 → 错误 → 多步 → 提交」组织，具体到可以直接写进规格。

## 1. 先问：这些字段真的需要吗

每增加一个字段，就多一次放弃的可能。开始设计前逐个问：

- 这个信息能不能不问（已有、可推断、可后补）？
- 能不能用默认值、自动填充、第三方授权替代？
- 用户答不上来时怎么办（「不知道 / 稍后再说」是不是有效答案）？

GOV.UK 的问题页原则是「知道自己为什么问每个问题，只问真正需要的」。这条比任何排版技巧都重要。

## 2. 字段设计

| 问题 | 做法 |
|---|---|
| 字段是什么 | 可见标签，放在输入框上方或左侧，同一系统内保持一致；placeholder 不是标签 |
| 是否必填 | 可选字段标「（选填）」；不要用星号标必填，也不要用颜色区分必填 |
| 为什么问 | 敏感信息（身份证、银行卡、收入）要说明用途与保护方式 |
| 输入格式 | 接受不同写法：手机号空格、姓名间隔号/生僻字、邮编大小写；能忽略的多余字符直接忽略 |
| 输入辅助 | 合适的 `type`、`inputmode`、`autocomplete`；移动端给对的键盘 |
| 单位与范围 | 数字字段写清单位、范围、精度；金额标注币种 |

字段类型的选择：

- 单行文本 / 多行文本：按内容长度选，长文本不要塞进单行。
- 单选（Radio）：选项全部可见、需要对比时用；选项多于 2 个、一般少于 5 个。
- 复选（Checkbox）：一组多选，需要提交后生效。
- 开关（Switch）：单个二选一、**切换即生效**；不要在需要提交的表单里用开关。
- 下拉：选项多于 5 个、需要省空间时用；选项少且需要对比时用单选组。
- 日期：记忆型日期用「日 / 月 / 年」三个输入框，示例写「27 3 2007」；日历不能是唯一输入方式。
- 上传：提前说明格式、大小、数量；上传中有进度、可取消；失败可单条重试。

## 3. 校验时机

**默认在提交时校验**，不要在用户离开字段时就报错——对输入慢的用户尤其不友好。已报错的字段可以改成实时校验，让用户看到「改对了」。

需要特殊处理的：

- **远程校验**（用户名是否被占用）：失焦或防抖后触发，显示「检查中」；请求可取消，最新一次响应优先；**校验服务不可用不等于通过**，要允许重试或放行并说明。
- **字数限制**：可以实时显示剩余字数，超限时提示；这是少数适合实时校验的场景。
- **密码规则**：在输入前说明，不要等提交才报错。

## 4. 错误呈现

出错时必须做到四件事：

1. **保留用户已填内容**（重新显示表单，不要清空）。
2. 页面顶部显示**错误摘要**，并把键盘焦点移到摘要。
3. 每个出错字段旁显示**字段级错误**，写清哪里错、怎么改。
4. 页面 `<title>` 前加 `Error: `（或等效的读屏告知），让读屏用户第一时间知道。

错误文案公式：**发生了什么 + 为什么（能确定时）+ 怎么办**。

| 差 | 好 |
|---|---|
| 输入有误 | 邮箱格式不完整，需要包含 @ 和域名，例如 name@company.com |
| 密码不符合要求 | 密码至少 12 位且包含一个数字；你目前是 9 位 |
| 提交失败 | 保存失败：网络中断。修改已保留，恢复网络后点「重试」 |

不要用错误码替代人话，但可以附错误码方便支持排查；不要把责任推给用户（「您输入了非法字符」）。

## 5. 多步表单

- **一问一页**：一页只问一件事，页面标题就是问题本身；适合长表单、政务/金融等不能出错的场景。
- 必备：返回链接、页面标题、继续按钮；浏览器返回键也要正常。
- 同一旅程不重复问已答过的信息；能预填就预填。
- 长流程要能保存草稿、能中断后继续，并在离开时提示未保存内容。
- 步骤条只用于「用户需要知道进度」的流程；步骤名要具体，不要只写「第 2 步」。

代价：页面变多、跳转成本上升。商业产品可以把几个问题合并到一页，但**不要把互相依赖、容易填错的问题塞进一页**。

## 6. 核对与提交

- 提交前给一次**核对答案**的机会：分组展示「问题 → 答案 → 修改」，每题一个「修改」链接，带隐藏文本说明改的是什么。
- 可选未填项显示「未提供」，不要留空。
- 提交按钮写清动作（「提交申请」「确认支付」），不要只写「提交」。
- 提交中要有 loading 且禁止重复提交；失败保留内容并可重试。

## 7. 身份与敏感字段速查

| 字段 | 关键规则 |
|---|---|
| 姓名 | 单个全名字段，不拆姓/名；接受各种字符与长度 |
| 地址 | 先邮编查找，找不到再手动输入；地址多行；不强制国家下拉 |
| 邮箱 | 单字段、允许粘贴、不要求重复输入；说明确认链接有效期 |
| 电话 | 单字段，允许空格与国际格式；说明用途 |
| 密码 | 允许粘贴、允许显示；说明长度要求，不要「四选三」；不要定期强制改密 |
| 银行卡 | 卡号单行自动分组、接受空格；显示卡类型；说明 CVV 在哪 |
| 银行账户 | 账号/排序码分行；提交前核对，错误代价高 |
| 身份证/证件号 | 接受空格与大小写差异，规范化后再校验 |

## 8. 验收清单

- [ ] 每个字段有可见标签，必填/选填标注一致
- [ ] 提交时校验；已错字段实时校验
- [ ] 错误摘要 + 字段错误 + 焦点移动 + 保留输入
- [ ] 远程校验有「检查中」、可取消、失败不等于通过
- [ ] 提交中禁止重复提交，失败可重试
- [ ] 长表单可保存草稿，离开有提示
- [ ] 只用键盘能完成整个表单
