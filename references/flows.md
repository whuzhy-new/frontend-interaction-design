# 流程与场景

组件级问题容易看见，流程级问题更贵：用户不是卡在一个控件上，而是卡在"下一步不知道去哪"。每个流程给：主任务、必须覆盖的状态、常见坑、验收动作。

## 1. 登录与注册

**主任务**：老用户 10 秒内进来；新用户不被打断地注册。

- 状态：未登录 / 表单校验中 / 提交中 / 凭证错误 / 账号锁定 / 需要二次验证 / 已登录跳转。
- 分开处理"账号不存在"和"密码错误"是安全与体验的取舍：面向消费者的产品通常合并提示（防枚举），企业内部可细分。
- 第三方登录失败要回到表单并保留已填手机号/邮箱。
- 验证码：倒计时可见、可重发、错误不刷新倒计时、粘贴可用。
- 注册后不要立刻弹订阅/资料完善；先让用户到达他本来要去的页面（保留 `redirect`）。
- 常见坑：登录墙挡住浏览（先看后登录通常转化更好，除非内容本身敏感）；密码规则只在提交后告知；会话过期时静默跳登录页，丢失当前操作。

**验收**：错误凭证有明确提示且不清空输入；验证码可重发；从受限页面登录后回到原页面。

## 2. 首次使用与引导

**主任务**：让用户尽快完成一次真实任务，而不是看完教程。

- 三种引导的取舍：空状态引导（最轻，推荐）> 上下文提示（场景触发）> 产品漫游（最重，大多被跳过）。
- 引导状态：未开始 / 进行中 / 跳过 / 已完成 / 不再显示。必须可跳过、可重看。
- 别把关键功能藏在引导里——引导关掉后要仍可发现。
- 常见坑：首次进入就弹三个模态；引导遮罩挡住真实操作；"下一步"按钮把用户带到与任务无关的页面。

**验收**：跳过引导后仍能完成任务；已看过引导的用户不再被重复打断。

## 3. 设置与偏好

**主任务**：看清当前值 → 改一项 → 确认生效。

- 状态：加载中 / 已加载 / 无权限 / 保存中 / 已保存 / 保存失败可重试 / 有未保存修改。
- 自动保存 vs 显式保存：自动保存需要可见的"已保存"与失败提示；显式保存需要脏状态提示与离开拦截。
- 危险设置（通知频率、隐私、删除账号）要写清后果，不要用默认值替用户决定。
- 常见坑：设置项没有默认值；改了没生效也不报错；多设备同步冲突无提示；保存成功但界面不更新。

**验收**：改一项保存后刷新仍保持；失败时保留修改并可重试；离开时有未保存提示。

## 4. 结账与支付

**主任务**：在最少步骤、最少意外下完成付款。

- 状态：购物车为空 / 库存不足 / 价格变动 / 优惠码无效 / 支付处理中 / 失败（可重试）/ 超时（可能已扣款）/ 成功。
- 支付中不可重复提交，且要区分"请求超时"与"支付失败"——前者应先查询订单状态。
- 费用透明：税费、运费、订阅周期在最开始或明确位置展示，不在最后一步突袭。
- 常见坑：强制注册才能结账；优惠码失败清空表单；订单成功后不告诉用户接下来会发生什么（邮件、发货时间）。

**验收**：断网重试不会重复扣款；价格变更有明确提示与确认；成功后给出订单号与后续步骤。

## 5. 搜索与筛选

**主任务**：从大量内容里收敛到少数结果。

- 状态：初始 / 输入中 / 加载 / 有结果 / 无结果 / 错误 / 已应用筛选。
- 筛选变化要立即反映在结果数与 URL 上（可分享、可返回）。
- 无结果给替代路径，而不是死胡同。
- 常见坑：筛选与分页不同步；清空筛选不恢复；筛选条件隐藏在折叠里看不出已生效。

**验收**：复制 URL 能还原筛选；清空筛选回到初始；无结果页有下一步。

## 6. 上传与长任务

**主任务**：提交任务后能放心离开，回来知道结果。

- 状态：待上传 / 上传中（单项进度）/ 处理中 / 部分成功 / 失败 / 超时 / 完成。
- 超过 10 秒的任务应可离开，通过通知或列表告知结果。
- 失败项单独重试，不要整批重来。
- 常见坑：刷新丢失上传；进度条到 90% 卡住无解释；大文件无大小限制提示。

**验收**：上传中断后能续传或明确重试；失败项可单独处理。

## 7. 权限与协作

**主任务**：知道"我能做什么、为什么不能"。

- 状态：只读 / 可编辑 / 待审批 / 无权限 / 权限变更中。
- 无权限时说明缺什么角色、怎么申请，而不是隐藏按钮让人猜。
- 多人同时编辑：显示谁在编辑、冲突如何合并、是否需锁定。
- 常见坑：按钮消失而非禁用（用户以为功能不存在）；权限变更后旧页面仍可提交。

**验收**：无权限用户能看到申请入口；并发编辑不静默覆盖。

## 8. 离线与弱网

**主任务**：不丢操作，恢复后能继续。

- 状态：在线 / 离线 / 重连中 / 有未同步修改 / 同步冲突。
- 离线时允许的操作要明确（草稿可编辑，提交不可），不要假装成功。
- 重连后自动重试并告知结果；冲突时给用户选择，而不是静默覆盖。
- 常见坑：离线白屏；请求失败无提示；重连后重复提交。

**验收**：断网编辑后联网，修改保留且结果可见；冲突有明确处理方式。

## 9. 错误与恢复

**主任务**：知道发生了什么、还能做什么。

- 分三类：可预防（约束、默认值、预览）、可恢复（重试、撤销）、不可恢复（说明与支持入口）。
- 全局错误页要给：发生了什么、影响范围、下一步（重试/返回/联系）、错误码。
- 部分失败必须分开呈现，不要一句"操作失败"覆盖所有。
- 常见坑：错误页无返回路径；重试按钮重复提交；错误信息含技术术语。

**验收**：模拟接口 500、断网、超时三种情况，用户都能知道下一步。

## 10. 批量与危险操作

批量分三型（统一动作 / 逐条补数据 / 文件导入），输入、校验与结果界面不同，见 [components.md 深挖：批量操作](components.md#深挖批量操作)。

**主任务**：一次处理多条，且能后悔。

- 选中态要显示数量与范围（含跨页），并提供"选择全部"。
- 批量删除优先"移入回收站 + 撤销"，而不是弹窗确认。
- 不可逆操作要写后果、要求二次输入或勾选确认。
- 常见坑：批量操作无进度；部分失败不说明哪几条失败；撤销时间过短。

**验收**：批量操作后能看到成功/失败明细；撤销可用且反馈明确。

## 11. 通知与打扰

**主任务**：重要的事不漏，不重要的事不烦。

- 分级：阻断（模态）> 需要处理（横幅/通知中心）> 结果告知（Toast）> 静默（日志）。
- 同一事件不要多渠道重复打扰（站内 + 邮件 + 推送）。
- 通知设置要可细化到类型与渠道，并提供"全部关闭"。
- 常见坑：Toast 承载必须阅读的信息；不可关闭的横幅；营销通知混在事务通知里。

**验收**：关闭某类通知后确实不再收到；关键通知不会被静默。

## 12. 移动端专项（横切检查，不按流程模板）

- 热区 ≥ 44×44 px；底部操作区避开安全区与手势条。
- 键盘弹起时输入框不被遮挡；表单可滚动到当前字段。
- 手势要有可见替代入口（滑动删除同时提供菜单项）。
- 返回手势与页面内导航冲突时，明确优先级。
- 常见坑：桌面端交互直接压缩到移动端；横屏失效；长页面无回到顶部。

**验收**：单手可达主要操作；键盘弹起不遮挡；手势有替代路径。

## 13. 列表页与工作台

一个列表页不是「一个表格组件」，而是筛选区 + 列表区 + 批量工具区 + 行操作 + 分页的组合。按区域拆状态，不要合并成一张表。

- **筛选区**：默认条件、已应用条件可见、清空、与 URL 同步（可分享/可返回）、筛选后回到第 1 页。
- **列表区**：加载（骨架）、空（首次/无结果/无权限区分）、错误（重试）、部分数据（分页未加载完）。
- **选择**：无选中/部分选中/全选；跨页选择要显示总数与范围；刷新或数据变更后重算选中集合。
- **行操作**：主操作直接可见，次要操作收进菜单；行内编辑要有保存/取消与校验。
- **批量任务**：进行中可见、可离开、完成后通知；部分失败给明细与只重试失败项。
- **分页**：页码、每页条数、跳转；筛选或排序变化后的回到第 1 页规则要写死。
- **权限**：无权限的操作是禁用 + 原因，还是隐藏，要与产品确认；禁用比消失更可解释。
- **验收**：用真实规模数据（如 200 行、7 行异常）验证，而不是 3 行样例。

## 14. 业务状态流转类操作

发货、审核、发布、关闭这类操作不是「删除」，但同样有后果：可能不可回退、会通知外部、会触发库存/财务。按「可回退性 × 影响面 × 外部副作用」判断：

- 可回退、影响小 → 直接执行 + 撤销窗口。
- 不可回退、影响可控 → 确认并写清后果（「将通知 12 位买家，运单不可撤回」）。
- 不可回退、影响大 → 阻断式确认 + 要求输入数量/名称，或分两步执行。
- 批量时先做「预检」：列出不可执行的行与原因，再让用户确认可执行部分。
