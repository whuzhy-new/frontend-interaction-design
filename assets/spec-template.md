# 交互规格模板（页面 / 流程）

页面与流程共用一份模板：页面按「区域」拆状态表，流程按「步骤」拆。单组件用 `component-spec-template.md`。

```markdown
# <页面/流程名> 交互规格

## 1. 任务与成功信号
- 谁：
- 场景：
- 要完成：
- 成功后看到：
- 失败时最坏的结果：

## 2. 状态模型（按层拆，不要合并成一张表）
### 2.1 页面级
| 状态 | 进入条件 | 表现 | 退出条件 |
|---|---|---|---|
| 初始 / 加载 / 空 / 部分成功 / 成功 / 失败 / 超时 / 无权限 / 离线 | | | |

### 2.2 区域级（每个区域一张：筛选区、列表区、工具栏、弹窗…）
| 区域 | 状态 | 表现 | 与其他区域的联动 |
|---|---|---|---|

### 2.3 行级 / 条目级（列表、表格、文件）
| 行状态 | 进入条件 | 表现 | 可执行动作 |
|---|---|---|---|

## 3. 元素规格（按类型写状态集）
| 元素 | 类型 | 状态集 | 触发与反馈 | 文案 | 边界与禁用条件 |
|---|---|---|---|---|---|
| 主按钮 | 操作型 | 默认/悬停/聚焦/按下/禁用/进行中 | | | |
| 表格行 | 数据型 | 默认/选中/禁用（原因）/加载 | | | |
| 复选框 | 操作型 | 未选/选中/部分选中/禁用 | | | |

## 4. 异步与错误
| 操作 | 加载 | 部分成功 | 失败 | 超时 | 幂等/防重复 | 结果界面与重试 |
|---|---|---|---|---|---|---|

## 5. 键盘与无障碍
- Tab 顺序：
- Enter/Esc：
- 焦点进入与归还：
- 读屏告知（持久 live region）：
- 对比度（文本 4.5:1；UI/焦点 3:1）：
- 非颜色传达：

## 6. 待确认
| 待确认 | 为什么重要 | 确认方法 | 找谁 |
|---|---|---|---|

## 7. 验收清单
每条写成「前置数据 + 操作 + 期望可见结果」：
- [ ] 主路径：给定 <数据>，执行 <操作>，应看到 <结果>
- [ ] 失败：断网/超时/500 时，应看到原因 + 重试，输入保留
- [ ] 并发：两人同时操作，后提交者应看到 <冲突提示>
- [ ] 键盘：只用键盘完成主任务，焦点不丢
```

## 填写提醒

- **分层**：页面、区域、行、任务各有状态，不要硬塞一张表；状态名统一用 `states.md` §0 的词表。
- **部分成功**：只要有批量或分步操作，就必须在状态表与异步表各出现一次。
- **待确认**：先按假设写完，再在表里列确认方法与负责人；影响结构的假设（权限、必填、可否导入）必须先问。
- **验收**：不能写成"断网有提示"，要写清给定什么数据、做什么操作、看到什么。
- **范围**：模板里删掉不适用的行，但不要删掉整节——少一节就是漏交付。
